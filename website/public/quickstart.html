Quickstart Guide

Quickstart

From a macro-enabled file to live editing

Five steps, about five minutes. At the end, saving a file in your editor changes the code in Excel, and your VBA is ready for Git.

Your setup The commands below follow your choice. The recordings were made with Excel.

Get the tool 1 min

You need Windows and a desktop version of Microsoft Office. Pick whichever way of running vba-edit suits you; all three give you the same commands.

If you have uv, prefix any command with uvx. It downloads the tool on first use and reuses that copy afterwards; uvx excel-vba@latest fetches a newer release.

PS> uvx excel-vba --help

With Python 3.11 or later, one package gives you all four tools.

PS> pip install -U vba-edit
PS> excel-vba --help

No Python at all: download excel-vba.exe, word-vba.exe, powerpoint-vba.exe or access-vba.exe from the Assets section of the latest release and run it from a terminal in its folder, with a leading .\ as PowerShell requires.

PS> .\excel-vba.exe --help

The executables are not code-signed, so Windows SmartScreen may warn on first start. The verification guide shows how to check the SHA256 checksums.

Stable or pre-release?

These three routes give you the stable release, 0.5.1. Everything in this quickstart works with it. The guide marks the few features that need the 0.6.0 pre-release and shows how to install it.

Let Office share its VBA project 1 min, once

Office blocks programs from reading VBA code until you allow it. In Excel, tick one box:

File›Options›Trust Center›Trust Center Settings…›Macro Settings›☑ Trust access to the VBA project object model

Then let the tool confirm it.

Access has no "Trust access to the VBA project object model" checkbox. What it needs instead is a database it trusts: keep the file in a trusted location (File › Options › Trust Center › Trust Center Settings… › Trusted Locations) or enable its content when Access asks.

Then let the tool confirm it can reach the VBA project.

Before you run the check: empty folder, Excel closed

In the stable 0.5.1 and the pre-releases up to 0.6.0a4, the check creates a scratch file named test with your application's file type (test.xlsm, test.docm, test.pptm, test.accdb) in the current folder, replaces or deletes a file of that name that is already there, and closes Excel when it is done. So run it from an empty folder, with Excel closed. Later versions use a temporary folder and leave an open Excel alone.

PS> excel-vba check
check
PS C:\Projects\budget> excel-vba check

If the last line says enabled, you are done here. excel-vba check all tests all four applications in one go.

Start an edit session 30 s

Open a terminal in the folder of your macro-enabled file and start edit. The sample here is a small budget workbook with five modules.

PS> excel-vba edit -f Budget.xlsm --vba-directory src
edit: start
PS C:\Projects\budget> excel-vba edit -f Budget.xlsm --vba-directory src

Three things just happened: vba-edit opened the file in Excel, wrote every module to a file in src, and began watching that folder. The session keeps running until you stop it.

Shorter still

Leave out -f and vba-edit uses the workbook that is currently active in Excel. Leave out --vba-directory and the files land next to it.

Edit, save, look 1 min

Open the src folder in your editor, change something in Reporting.bas and save. The terminal reports the change, and the module in the VBA editor has it too. New files become new modules.

edit: two saves later
1 change detected
Processing changes in Reporting.bas
Successfully processed: Reporting.bas
Reporting.basForecast.bas
'@Folder("Reports")Option Explicit Public Sub BuildMonthlyReport()    Dim total As Currency    total = SumColumn(Sheet1.Range("B2:B13"))    Sheet1.Range("B14").Value = total    MsgBox "Total spend: " & FormatMoney(total)End Sub

Your side: the file with line 8 changed (a code listing, not a screenshot).

One direction

A plain edit session copies changes from your files into Office, not the other way round. Code you type into the VBA editor while it runs stays there until you export it. Deleting a module's file deletes that module in Office. If you want both directions, the guide covers the experimental --bidirectional mode.

Stop, and keep the history 1 min

Press Ctrl+C in the terminal to end the session. The file stays open in Excel, already saved with your changes.

edit: stop
^C
Stopping VBA editor...
VBA editor stopped.

Your VBA now exists as text, which makes it a normal citizen of Git. Commit the exported folder once, and every later change shows up as a readable diff.

git: baseline, edit, diff
PS C:\Projects\budget> git init -q -b main
PS C:\Projects\budget> git add src
PS C:\Projects\budget> git commit -q -m "Baseline export of Budget.xlsm"

Where next

You have the core loop. Three good next stops:

Using UserForms or class attributes?

Add a header option before you export forms, so their layout survives the round trip.

--in-file-headers

Tired of typing options?

Put them in a config file. A small GUI writes it for you.

excel-vba config-gen

Set up your editor

Two settings make VS Code read VBA files with the right encoding and syntax.

"files.encoding": "windows1252"
