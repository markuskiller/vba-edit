Quickstart Guide

Excel · Word · PowerPoint · Access

Write VBA in the editor you love.

vba-edit keeps the VBA project inside your Office file in sync with plain text files on disk. Edit them in VS Code or any other editor, review changes in Git, let an AI assistant help. Every save lands in Office.

How it works

Your VBA project, as files

The VBA editor built into Office keeps code locked inside the document. vba-edit talks to Office over its automation interface, writes each module to a file, and puts your changes back.

Office VBA project

The modules inside your .xlsm, .docm, .pptm or .accdb.

  • standard modules
  • class modules
  • UserForms
  • document modules
export →
← import
← edit, on save
⇄ bidirectional

Files on disk

One file per module, in a folder you choose. Any editor can open them.

  • Module.bas
  • Class.cls
  • Form.frm + .frx
  • optional .toml config
your tools →

Once code is text, the rest of the software world opens up.

What you get

One small tool per Office app, six commands

excel-vba, word-vba, powerpoint-vba and access-vba share the same commands and options. Each card opens the matching chapter of the guide.

01 / edit

Live editing

Export once, then watch the folder. Saving a file updates the module in Office within a second or two.

excel-vba edit -f Budget.xlsm 02 / export · import

One-off transfers

Take a snapshot of all modules, or push a folder of files back into a document.

excel-vba export --vba-directory src 03 / --bidirectional experimental

Two-way sync

Edits made in the VBA editor flow back to your files as well. Conflicts are paused, never overwritten.

excel-vba edit --bidirectional --in-file-headers 04 / headers

Classes and UserForms, intact

Keep module attributes and form layouts with the code, in the file or beside it.

--in-file-headers · --save-headers 05 / folders

Rubberduck folders

'@Folder("Domain.Billing") annotations become real directories, and back.

--rubberduck-folders 06 / filter 0.6

Pick your modules

Include or exclude modules by name or glob. Leave vendor code and locked forms alone.

--include "Rep*" --exclude "Vendor_*" 07 / references

Library references

List, validate, export and restore the references of a VBA project as a TOML file.

excel-vba references list 08 / config

Config files and a GUI

Store a project's options in TOML. A small window builds the file for you.

excel-vba config-gen 09 / safety

Guard rails

Prompts before files are overwritten, forms that refuse to lose their layout, failed updates rolled back.

--force-overwrite to skip prompts

Sample use cases

Start from what you want to do

Each of these is a worked example in the guide, with the commands to copy.

Put a workbook under version control

Export once, commit, and review every later change as a normal diff.

Let an AI assistant work on your macros

Give the assistant a folder of files instead of a locked binary, and test each change live.

Share one setup across a team

A config file and a references file in the repository make every checkout behave the same.

Edit your code, not the vendor's

Exclude third-party modules and locked forms from every command.

Refactor offline, import selectively

Work without Office running, then push back only the modules you touched.

Work on an Access database

Standard and class modules, plus the code behind forms and reports.

Where the project stands

November 2026: 0.5.1 is stable, 0.6.0 is in pre-release

These docs describe 0.6.0. Features that are not in the stable release yet carry a 0.6 mark, and the two-way sync is marked experimental.

ReleaseWhereWhat it adds
0.5.1 stablePyPI, uvx, Windows binariesEverything in these docs except the items below.
0.6.0a4 pre-releaseTestPyPI and the GitHub pre-release pageBidirectional editing with the focus-loss trigger, --include / --exclude, export that leaves open documents alone, an import summary with exit code, Access form and report code, several UserForm import fixes. Needs Python 3.11 or later.

vba-edit is beta software. Keep a backup of important Office files, and keep the code in version control.
